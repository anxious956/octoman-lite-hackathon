      Each step and the AWS service behind it

      Step on the pageAWS serviceWhat it does
      Order arrivesAPI Gateway (HTTP API) + LambdaChecks the order and starts the Step Functions workflow; the order id is the execution name, so a repeat cannot run twice.
      Check the shelfDynamoDB transactionTakes the units off the shelf only if enough are left, and records the order, in one all-or-nothing step.
      Update all 4 storesStep Functions Parallel statePushes the new quantity to the four Amazon stores at the same time (mock mode: the Amazon Selling Partner API request is built, not sent).
      Convert to dollarsLambda + ECB reference ratesConverts the local price to US dollars with the European Central Bank's daily rates.
      Low-stock warningDynamoDB (direct from Step Functions)Writes a warning when a product falls below its warning level.
      Save receiptLambda + S3Stores a receipt file and marks the order as sold.

      Why it cannot oversell

      • The shelf is one number in one database row. Every store sells from it; none keeps its own copy.
      • “Check there is enough” and “take it off the shelf” happen in one step that the database does all at once, so two orders can't both take the last one.
      • An order that asks for more than is left is stopped at that step and recorded as blocked. Nothing is sold.

      About this demo

      • Products and orders are made-up demo data.
      • The Amazon stores run in mock mode: the real Amazon Selling Partner API request is built but not sent, so no Amazon seller account is involved.
      • Every part is serverless and pay-per-use: it costs nothing while nobody is ordering.
